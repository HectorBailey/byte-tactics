# Debug allocator, crash reporting, diagnostic windows and profiling

Status: finished. `debug/debug_lib` owns 267 annotations from `0x4d80b0` through `0x4e42a0`. Of these,237 are in [debug_lib.cpp](../../../src/debug/debug_lib.cpp),27 in its twenty numbered companion files, one in [free_block_map.cpp](../../../src/debug/free_block_map.cpp), one in [memory_status_dialog.cpp](../../../src/debug/memory_status_dialog.cpp) and one in [runtime/basic_string.cpp](../../../src/runtime/basic_string.cpp). Allocation, diagnostics and generated container support share this interval. The optional adapter in [debug_helper](debug-debug-helper.md) is a different module.

## Responsibilities and connection to gameplay

The library supplies the allocation functions used throughout maps, units, GUI, particles, archives, sounds and networking. It also provides page protection, retained freed-block descriptions, exception logging, stack walking/symbolization, memory/performance windows, native processor counters, timers and diagnostic registry preferences. It does not define ship rules, target eligibility or construction geometry. Its effects on those systems are memory availability, allocation lifetime, diagnostics and timing overhead.

There are two allocation modes: ordinary CRT malloc/realloc/free with counters, and memfussy VirtualAlloc reservations/commits with guard space and an address-keyed live map. Independent switches control initial fill and protection. Native pointer width,4096-byte page assumptions, old Win32/IMAGEHLP interfaces and original CPU/driver contracts are part of the implementation, not modern portability promises. No runtime diagnostic window, external driver or crash path was invoked for this documentation.

## Command-line settings and one-time initialization

FindCommandLineSwitch (`0x4d9f60`) scans the complete Windows command line at every character, case-insensitively. It requires the matched spelling to end at NUL, whitespace or equals, but does not require a token boundary before it. It returns the address immediately after the spelling. Embedded/path occurrences can therefore count; this is not a quoted command-line parser. Null/empty names return null.

CommandLineSwitch (`0x4d9fe0`) starts with the supplied default, checks either enabling spelling, then either disabling spelling. Disable wins regardless of textual order. CommandLineNumber (`0x4da040`) finds its spelling, skips spaces/tabs/equals and sscanf-parses decimal or a leading0x hexadecimal, retaining default on failed conversion. The descriptive name and extra constructor parameter are unused here. IsDebugKeyword (`0x4da0e0`) checks nineteen configured keyword prefixes without requiring end-of-word, a different recognition rule.

| Setting | Literal policy |
| --- | --- |
| IsMemFussy, `0x4d80d0` | Lazy switch with default g_memFussyDefault, enabled by -memfussy or -memfrontalign, disabled by -memnofussy. Marks the setting queried before construction. |
| SetMemFussyDefault, `0x4d80b0` | Sets default one only before the first query; cannot change an already cached switch. |
| IsGonzo, `0x4d8140` | Default one, with -gonzo passed as the disabling spelling. The name alone does not mean this flag enables it. |
| IsMemSet, `0x4d8200` | Default zero, enabled by -memset, disabled by -memnoset. |
| GetMemSetValue, `0x4d8260` | Parses numeric text after -memset; default `0xdeadbeef`. |
| IsBackAlign, `0x4db760` | Default one; -memfrontalign disables back alignment while also enabling memfussy through the separate switch. |
| SetFpuFussy, `0x4df160` | Default off; -fpufussy unmasks divide-by-zero and invalid floating exceptions, -fpunofussy masks them. Other exception mask bits are preserved. |

The local-static atexit callbacks for these switch objects (`0x4d8130`, `0x4d8190`, `0x4d8250`, `0x4d82b0`, `0x4db7b0`, `0x4df1d0`) are empty. Their existence does not imply settings are persisted or memory is audited at exit. GetDebugLibVersion (`0x4da0b0`) returns996.

InitDebugSupport (`0x4da1d0`) is guarded globally and sets that guard before doing work. Optional -debughelper parses an equals-integer, calls DebugFunc1 through the local [fatal adapter](../../../src/debug/debug_lib_4da120.cpp) and then aborts unconditionally, even after success. That adapter uses cdecl and shows debugger/message-box diagnostics on missing DLL/export, unlike the separate nonfatal stdcall adapter module. The debug startup path is not a health check that normally returns to gameplay.

Unless caller flags suppress them, startup installs the unhandled exception filter (bit two suppresses), applies FPU policy (four) and creates the debug thread (eight). InitFullDebugSupport (`0x4da3e0`) passes zero. Thread creation uses an8000-byte requested stack and then busy-spins until a nonvolatile global running byte changes, with no timeout/yield or handle close. RunDebugThread (`0x4da2e0`) temporarily raises its priority, constructs memory/performance windows, restores priority, sets running and pumps messages until WM_QUIT. GetMessage error minus one simply loops again. DebugThreadProc (`0x4da2c0`) delegates; HandleDialogMessage (`0x4da380`) walks to the root parent and lets IsDialogMessage handle navigation before ordinary translation/dispatch.

## Allocation API, locking and counters

GetAllocLock (`0x4da780`) lazily initializes a recursive Win32 critical section. Its destructor/atexit callback is empty, so no DeleteCriticalSection occurs here. GameAlloc (`0x4d83c0`), GameRealloc (`0x4d84c0`) and GameFree (`0x4d85b0`) hold it around their work, including callbacks. Debug allocation/free/reallocation take the same lock internally; recursive ownership permits those nested calls. This does not make every caller's borrowed pointer safe after free.

GameAlloc chooses debug block or malloc. Failure invokes a configurable out-of-memory callback and retries as long as callback remains nonnull, without a retry cap. A callback that returns without freeing memory/changing policy can loop forever under the allocator lock. Successful ordinary malloc counts the requested size. Optional memset fills exactly the requested bytes after either mode succeeds. SetOutOfMemoryHandler (`0x4d8e50`) replaces and returns the prior callback.

GameCalloc (`0x4d8460`) multiplies count/size in unsigned arithmetic without overflow checking, allocates and zeroes that computed byte count. GameStrdup (`0x4d8610`) rejects null, allocates strlen plus one and copies. GetBlockSize (`0x4d8360`) returns zero for null, a tracked requested size in memfussy mode or CRT _msize otherwise. Changing heap mode after allocations would invalidate that ownership assumption; these switches are cached to avoid routine mode changes.

GameRealloc in ordinary mode obtains old _msize, special-cases null/zero, then reallocates. Success or requested size zero decrements old accounting and increments new requested accounting as appropriate. Failure with nonzero size retains original block and counters, invoking/retrying the OOM callback. It does not initialize newly grown bytes with GetMemSetValue. Debug reallocation (`0x4dba40`) allocates a new block, copies min(old requested size,new size), then frees old; failed allocation preserves old. Size zero frees old and returns null. It also does not guarantee fill initialization of the new tail through this inner allocation path.

GameFree ignores null; ordinary mode counts _msize then free, so accounting can subtract rounded CRT capacity after having added requested size. Unsigned live/current counters can underflow or drift even without a new gameplay allocation. Debug mode ignores pointers absent from the exact live map. Wrappers GameAllocIgnoreTag (`0x4d83b0`), GameAllocShared (`0x4d8450`), GameAllocThunk (`0x4d8660`), GameReallocTagged (`0x4d84a0`), GameReallocIgnoreTag (`0x4d8580`), GameFreeThunk (`0x4d85a0`) and GameFreeIndirectThunk (`0x4d8670`) delegate. In this build tag/name arguments are ignored by those wrappers; they do not automatically label BlockInfo records. Some provisional declarations use void while leaving the callee's result in the original return register, so caller views may treat them as pointer-returning ABI adapters.

CountAlloc (`0x4da7d0`) increments allocation serial/live count, their peaks, total requested bytes and current/peak bytes. Total requested uses a low part plus high base-one-billion carry, subtracting one billion only once per call rather than arbitrary-width normalization. CountFree (`0x4da840`) subtracts count/bytes. ResetAllocStats (`0x4da860`) zeroes live/serial/bytes/committed/wrap counters without enumerating or freeing existing blocks; subsequent frees can underflow this freshly reset observation. Dialog counters are diagnostics, not authoritative allocation ownership.

## Fill checking and protected pages

FillPattern (`0x4d82c0`) repeats a dword then copies its low trailing bytes. [CheckFillPattern](../../../src/debug/debug_lib_4d8310.cpp) compares the same layout and triggers an x86 breakpoint for each mismatch rather than returning a Boolean. GetDebugFillPattern (`0x4db7c0`) returns `0xcccccccc`, distinct from initial requested-byte fill. IsNearFillPattern (`0x4d81a0`) requires fill enabled/nonzero and tests a value within signed range of four rotated byte alignments; range/overflow are not validated. AllocNotifyNop (`0x4d83a0`), NopAbortHook (`0x4d8390`) and AvWriteDetectStub (`0x4d8680`, returns zero) have no hidden allocator recovery/protection analysis.

ProtectPages (`0x4d86b0`) acts only while IsGonzo is true. It rounds the start up and end down to whole pages strictly contained in the supplied range, calls VirtualProtect and ignores its result/old protection. ProtectPagesReadOnly (`0x4d8690`) uses PAGE_READONLY two; ReadWrite (`0x4d86f0`) four. Partial endpoint pages remain untouched. ProtectBlock (`0x4d8720`) gets block size; in memfussy mode RoundRangeToPages (`0x4dbb90`) expands to covering pages, then delegates. Ordinary heap blocks protect only fully contained pages. ReadOnly/ReadWrite block wrappers are `0x4d8710`/`0x4d8780`. These operations are unrelated to game ownership/visibility permissions.

## Virtual reservation and allocation layout

[GetFreeBlockSet](../../../src/debug/debug_lib_4db610.cpp) lazily creates a pooled map of address/length free reservations. It initially tries four256 MiB regions, reserving len plus8192 each, halving on allocation failure or an end above2 GiB, down to64 KiB. The tracked free portion excludes the extra8192 bytes. GrowReservation (`0x4db450`) follows a similar strategy, increasing initial size for large requests and refusing below-request/minimum reservations. It accumulates reserved total but does not release successful regions on individual free.

[TakeFreeBlock](../../../src/debug/free_block_map.cpp) uses an address-ordered map, starting near g_lastAllocOffset and reusing a predecessor that contains the desired range. It scans, wrapping at most twice and counting wraps, extracts a large-enough block, returns prefix/suffix pieces and advances the remembered offset. No fit grows reservation and recurses. AddFreeBlock (`0x4db000`) coalesces exactly adjacent successor/predecessor intervals, not arbitrary overlapping corrupt ranges. Address arithmetic assumes no overflow.

[AllocDebugBlock](../../../src/debug/debug_lib_4dacf0.cpp) normalizes zero to one for page calculations. Need is request rounded up to4096; want is twice that rounded size. Want below need catches some overflow, not every arithmetic failure. It removes want from reserved free space and commits only need as read/write. Commit failure returns the reservation to the free map. Extra want space remains uncommitted as a guard region.

Slack is negative requested size modulo4096. Back alignment fills slack before the returned pointer and shifts the pointer so the requested bytes end at the committed boundary; front alignment leaves base unchanged and fills slack after requested bytes. The live map records returned pointer, original requested size, serial and flags/tag, with no name. CountAlloc uses original request; committed accounting also rounds original request, so zero allocations can commit a page while adding zero committed bytes. They return a nonnull pointer if allocation succeeds, but do not have a normal positive-length payload.

[FreeDebugBlock](../../../src/debug/debug_lib_4db7d0.cpp) finds the exact returned pointer, checks front/back slack against `0xcccccccc`, retains the48-byte record, erases live entry, subtracts counters, rounds pointer down to a page, decommits need and returns want to the free map. VirtualFree's return is ignored. A changed boundary pattern can trap during free; double/foreign free is silently ignored when no record exists. Guard reservations may catch overruns immediately at an uncommitted page, while slack corruption is discovered later by checks; neither detects every intra-block logic error.

The freed history is a vector of up to8192 records, then overwrites index totalCount AND8191. GetFreedBlockRing (`0x4da9f0`) creates its storage descriptor through GlobalAlloc. DescribeFreedBlocks (`0x4dabb0`) scans physical vector order backward, not a chronologically rotated ring after wrap. It reports containing records only while nominal room above100. FormatBlockInfo ignores its size argument, so the room check is approximate. No freed payload is kept alive, only descriptions; address reuse can yield multiple historical matches.

## Block descriptions and generated tree/vector support

BlockInfo constructors (`0x4d87f0`, `0x4d8820`) store address/size/serial/name/tag; the default leaves tag unspecified. SetName (`0x4d8850`) keeps at most31 characters. FormatBlockInfo (`0x4d8790`) formats size/address/serial and optional name with unbounded sprintf. FindBlocksAroundAddress (`0x4daa30`) gets strict upper bound then predecessor under allocator lock; DescribeAddress (`0x4dab10`) formats the predecessor if its half-open range contains the address, otherwise a generic message.

BlockHistory constructors (`0x4d8bd0`, `0x4d8c00`) build allocation/free TraceRecords and retain a BlockInfo. FormatBlockHistory (`0x4d8c50`) appends the allocation site and optionally freed site using remaining-length calculations that do not bound every earlier strcat. FUN_004d8d40 only formats into a2000-byte local and discards it. RunningStats (`0x4d8ae0`, name setter `0x4d8b30`, AddSample `0x4d8b60`) counts, tracks unsigned min/max and a64-bit total, initializing min/max from the first sample. It does not compute a mean until a consumer divides the total.

GetBlockMap (`0x4da8d0`) owns an address-keyed red-black live-record tree with64-byte nodes; free reservations use24-byte nodes. Both use separate8192-byte GlobalAlloc pools, carving128 and341 full nodes respectively. Generic pool allocators (`0x4ddd70`, `0x4dddf0`) accept a size, retry OOM callbacks and return free-list nodes; zero size loops forever while refilling and oversize requests can leave no node before a dereference. Internal node creation likewise assumes a successful allocation. Pools bypass GameAlloc to avoid recursively tracking their own bookkeeping allocations.

The owned tree methods in `0x4dbbc0..0x4dde70` cover unique insert-or-find, explicit insert, erase-returning-successor, begin, bounds, exact lookup, predecessor/successor, rotations, node creation and iterator/insert-result copies. Insert links a red node, recolors/rotates until invariants hold and blackens root. Erase transplants the in-order successor for a two-child node, repairs black height, updates head extrema/count and returns storage to its matching node pool. The head is end and caches root/min/max; the shared Nil is a separate sentinel. Iterator arithmetic means tree traversal, not pointer-stride indexing.

FreeBlockMap routines named lower_bound at `0x4dc620` and LowerBound at `0x4dd250` actually find the first key strictly greater than the input, matching upper-bound comparison in their bodies. BlockMap::LowerBound (`0x4ddc90`) finds first greater-or-equal; Ubound (`0x4dd7d0`) is strict upper; Find (`0x4dce00`) combines lower bound with equality. These literal comparisons govern coalescing and address descriptions despite inconsistent names. std::_Lockit scopes protect STL shared support, while the outer allocator critical section supplies the larger allocator operation lock.

The generated vector insert (`0x4dd8c0`) is instantiated from the existing MSVC VECTOR header: insufficient capacity grows to old size plus max(old size,insertion count), copies prefix/new entries/suffix then frees old storage; sufficient capacity shifts/constructs the tail. Its custom allocator uses GlobalAlloc/GlobalFree and copies48-byte descriptions, with no payload destruction work. Source-header contracts were read without compiling. Tree/vector support is included in the267-entry accounting, not a separate gameplay module.

## Stack capture, TLS limits and symbolic lookup

[TraceRecord constructors](../../../src/debug/debug_lib_4d8870.cpp) capture up to14 return addresses plus one stack word, storing source/id. Long source names keep their final63 bytes. [IsOutsideStack](../../../src/debug/debug_lib_4d8d70.cpp) records current ESP in thread-local state, lazily queries the memory region end and accepts ranges only between current pointer and that end. Query failure sets the cached-known flag before returning failure, so later calls do not retry automatically. GetStackLow/High (`0x4d8df0`, `0x4d8e20`) invoke that helper then return TLS boundaries. These are the current thread's observed stack region, not all process stacks.

WalkFrameChain (`0x4de600`) includes supplied EIP unless skipped, prefers IMAGEHLP when available, otherwise follows EBP links with live-stack, monotonically increasing pointer and nonzero return checks. It bounds output to the supplied count in normal use and copies up to copyMax stack dwords, zeroing the unused tail. The initial EIP insertion happens before checking max. StackTrace::CaptureStack (`0x4d9c60`) uses thirty addresses and2048 dwords; FormatStackReport (`0x4d9ca0`) formats raw call addresses and stack words into a large member buffer. This is not disassembling instructions despite one provisional comment.

MappedFile constructor/Open/Close (`0x4e1560`, `0x4e1590`, `0x4e1650`) opens readonly, creates mapping and maps a view, using state1/2/3 for open/mapping/view failures. Failure paths close acquired handles. Reopening does not first close old resources or reset all state; Close does not null handles/view, so repeated close is unsafe. LoadedImage (`0x4ddf00`) combines live PE headers and a mapped executable file; it trusts DOS/NT header offsets and debug-directory structure. FPO helpers (`0x4ddfa0`, `0x4ddfe0`, `0x4de020`) find debug type three in mapped raw data, count16-byte records and binary-search instruction RVA within a procedure. File bounds/order are assumed. FunctionTableAccess (`0x4de0a0`) and GetModuleBase (`0x4de100`) preserve ABI-returned values through provisional void declarations; CloseLoadedImage (`0x4de0f0`) closes its mapped storage.

LoadImageHelp (`0x4de180`) is lazy, default enabled with explicit enable/disable switches, but a forced call can bypass disabled preference. It resolves mandatory SymSetOptions, SymInitialize, SymCleanup, StackWalk, SymFunctionTableAccess and SymGetModuleBase, with optional symbol/line/undecoration functions. Search path uses windir plus executable directory. Initial SymInitialize failure switches to local FPO/module callbacks, disables symbol/line lookup and retries without process invasion. Failed initialization is cached. Missing mandatory exports can return while leaving a loaded module/partial pointers; UnloadImageHelp (`0x4de110`) calls SymCleanup whenever module exists without independently checking that export, then frees/nulls pointers. It clears loaded but does not explicitly clear the inited byte.

WalkStack (`0x4de700`) uses i386 StackWalk, skips requested frames and emits supplied EIP on immediate failure with an empty count. GetLineFromAddress (`0x4de550`) resolves source lines and reports GetLastError. TryEnableImageHlpLines (`0x4de4d0`) requires enabled preference and either line or symbol export, then FormatCallStack (`0x4dea00`) prints paths/line numbers, symbols/displacements and optional undecoration, or raw grouped addresses. Its symbolic branch calls SymGetSymFromAddr unconditionally even when only the line export satisfied the earlier either/or test. Buffer reservations are approximate, per-line formatting unbounded and per zero would divide by zero in grouping. A found-symbol flag persists across later frames.

GetSourceFilePath (`0x4de8a0`) leaves names containing backslashes as supplied, otherwise caches roots derived by stripping the last component of MSDevDir (and any semicolon suffix), appends VC MFC/CRT source paths and tests MFC before CRT via FileExists (`0x4de810`). It does not strip the path to just a drive despite its provisional comment. CallSite::FormatCallSite (`0x4d89b0`) combines resolved source/id and stack report; preceding strcpy/sprintf operations can exceed nominal size before the stack formatter receives remaining space.

## Exception log and fatal shutdown

ReportException (`0x4d8e60`) is globally one-shot: it sets g_errorLogWritten before doing I/O or stack processing, so failed reporting is not automatically retried. It captures context EBP/ESP/EIP, derives ErrorLog.txt next to the executable (fallback C root), opens/appends and writes an early crash header followed by handler/system/exception/register/code/stack/FPU/debug-register details. GetExceptionName (`0x4d98c0`) recognizes24 statuses, including access violation, integer/floating faults, stack overflow and Microsoft C++ exception, with a generic fallback.

The reporter tests file handle against zero rather than INVALID_HANDLE_VALUE; failed opens can still flow into file APIs. It directly reads16 instruction bytes at EIP and trusts context pointers/exception parameter count. Access-violation read/write is derived from parameter zero, while its specialized write-to-readonly detector always returns zero in this build. Parameter line wrapping tests remainder modulo three equal three, which is impossible. Most formatting is unbounded despite a large stack log buffer. A failure while generating the report is not protected by a general nested recovery wrapper here.

FormatSystemInfo (`0x4ded60`) records wall-clock time, executable/user/machine, file size/local timestamp, UTC PE link time, library version/date, processor count, physical memory and thread stack boundaries into a2000-byte temporary before copying with caller length and terminating. Zero destination length writes before the target. It shares the zero-versus-invalid file-handle issue. NormalizeLineEndings (`0x4da3f0`) moves text to the buffer tail then rewrites lone CR/LF as CRLF, collapsing pairs. Its preliminary space budget counts LF only; many lone CRs can expand beyond its estimate.

[FatalError](../../../src/debug/debug_lib_4d9ab0.cpp) appends supplied message, deliberately raises a breakpoint inside an SEH reporting wrapper, shows a system-modal message and calls AbortProgram (`0x4da0c0`), which invokes a no-op hook, raises SIGABRT and exits code3. The unhandled exception adapter (`0x4da2a0`) calls ReportException; its provisional void declaration leaves the reporter's zero return in the native register. ShowDebugMessage (`0x4da120`) emits debugger output plus message box. These functions diagnose/terminate, not roll back a partially loaded map or return a recoverable error object.

## Dialog templates, windows and memory observations

GetDialogTemplate (`0x4da480`) allocates/copies built-in memory `0x66` (416 bytes), performance `0x67` (704), or assert `0x81` (992) templates from [debug_dialogs.cpp](../../../src/debug/debug_dialogs.cpp). Unknown IDs return null. Allocation failure is not checked before memcpy. ShowDialogBox (`0x4da4f0`) and CreateDialogFromTemplate (`0x4da540`) use stored debug instance and free copied template after modal/modeless creation. SetDebugLibInstance (`0x4d9f30`) stores process-attach instance; GetDebugLibInstance (`0x4d9f50`) returns it. The assert template's existence does not turn empty console Assert into an implemented assertion command.

MemoryStatusDialog construction (`0x4e0570`) initializes window/rate observation state, reads WorkingSet preference and creates the modeless template through `0x4e05c0`. GetMemoryStatusDialog (`0x4e1410`) is lazy; ShowMemoryStatus (`0x4e1400`) displays; StartMemoryStatus (`0x4e1460`) always constructs and shows only for -memorystatus. Visibility (`0x4e05f0`) focuses/restores, starts a200ms timer, or hides/saves/kills timer/unloads PSAPI. An early show request latches until window creation. MemoryStatusDlgProc (`0x4e06a0`) stores object in32-bit window user data and forwards messages.

[HandleMemoryStatusMessage](../../../src/debug/memory_status_dialog.cpp) registers Alt+End, toggles working-set persistence, supports stats reset/help/hide and refreshes only while visible. It saves moved position, computes allocation delta divided by elapsed high-resolution time and keeps a ten-sample rate average. Zero elapsed has no explicit division guard; reset serial can produce negative observations, with displayed rate clamped to zero. It formats current/peak/requested/live/committed statistics and optionally working set, updating window only when text changed. These snapshots are not taken under the allocator lock throughout, so values can reflect adjacent instants.

FormatWorkingSet (`0x4e07e0`) uses a separate lazy critical section (`0x4e06f0`) and loads PSAPI/QueryWorkingSet once per availability cycle. It queries at most once every ten calls into a400000-byte stack structure, then classifies pages by address/flag: C0000000 through E0000000 as page tables, low bit `0x100` as shared, otherwise private. It tracks total/peak and prints counts times4096 with commas. These are implementation-era heuristics, not a general semantic proof of ownership. Buffer failure returns false; returned page count is trusted. UnloadPsapiImpl (`0x4e0740`) frees/nulls but leaves initialized true, preventing retry; UnloadPsapi (`0x4e0790`) resets initialized false so reopening may retry. Lock atexit is empty.

## Performance counters and report-name lifetime

HasPerfCounters (`0x4e1680`) caches its first OpenGdperf result. [OpenGdperf](../../../src/debug/debug_lib_4e35b0.cpp) checks CPU vendor GenuineIntel, opens the NT GDPERF device or Windows9x GDPERF.VXD and reads the legacy family nibble. Families five/six are accepted; others become four. Device-ready can be set before discovering an unsupported family, so handle-ready and capability result differ. Family six initializes both clock counters. CloseGdperf (`0x4e3710`) clears ready and closes device, but does not reset HasPerfCounters' attempted/available cache.

[ProgramPerfEvent](../../../src/debug/debug_lib_4e3750.cpp) checks counter zero/one, ready, descriptor family and allowed-counter bits. Family five reads/modifies the packed control register, clears selected counter and writes mode/event bits; family six writes the appropriate event-select register. Intermediate family-five driver failures are not all propagated. ReadGdperf (`0x4e38e0`) requires DeviceIoControl `0x9c406404` to return exactly8 bytes; WriteGdperf (`0x4e3930`) uses `0x9c406400` with12-byte input and requires zero output. GetCpuFamily (`0x4e39a0`) returns cached family. No driver was opened or installed for this work.

IsPentiumOrBetter (`0x4e1700`) excludes processor-type constants386/486 and otherwise returns true. The separate [CPU feature probe](../../../src/debug/debug_lib_4e16b0.cpp) tests CPUID leaf-one EDX bit `0x800000` and caches it in provisionally named g_cpuHasTsc. The actual tested bit is documented rather than inferring a timestamp-counter guarantee from that name.

InitPerformanceEvents (`0x4e1be0`) starts with17 Pentium Pro events, reads saved settings and chooses8 Pentium events for available counters on family below six. [perf_counters.cpp](../../../src/debug/perf_counters.cpp) supplies IDs, labels, allowed counters and related-denominator IDs: cache reads/writes/misses, misalignment, floating operations/microcode/multiply/divide, clock ticks, fetch/retirement and branch prediction. It matches persisted IDs then falls back to first event when selected text missing. SyncPerformanceSettings (`0x4e1b10`) reads/writes enabled-in-release (default off), priority raising (on), debugger display (off), window display (on), auto pairing (on) and both event IDs under CavedogLibrary/PerformanceSettings.

NameTable (`0x4e17c0`, lazy accessor `0x4e1a90`) is a red-black map from borrowed C-string pointer keys, compared case-sensitively with strcmp, to copied500-byte reports. Keys are not duplicated or reference-counted. Timer/caller name storage must outlive its report entry. NameKey::LessThan (`0x4e1a30`) first tests pointer inequality, then content. [Upsert](../../../src/debug/debug_lib_4e1990.cpp) holds its own global critical section, erases an existing key then inserts replacement; changed is set only for a newly introduced key, allowing existing displayed text to refresh without rebuilding every row.

The name map uses520-byte pooled nodes, a shared Nil/reference count and8192-byte GlobalAlloc slabs. Owned support includes erase/subtree traversal (`0x4dfea0`, `0x4e03f0`), next/min (`0x4e0450`, `0x4e04e0`), clear/begin (`0x4e18c0`, `0x4e2240`), unique insert (`0x4e2250`), [lower bound](../../../src/debug/debug_lib_4e2580.cpp), [node insertion](../../../src/debug/debug_lib_4e2620.cpp), rotations/result copy/node creation/previous/pool (`0x4e2950..0x4e2b60`). They use the same red-black algorithm and pool ownership as allocation maps, but different keys/record sizes. Clear marks changed; destruction returns active/head nodes to the pool and drops shared Nil when its reference count reaches zero. It does not free borrowed name strings.

## Performance window behavior

PerformanceDialog (`0x4df1e0`) sets an initial unique selected key, initializes events and creates template `0x67`; failure shows a message. GetPerformanceWindow (`0x4dfd10`) provides the static object. Its generated teardown [trigger](../../../src/debug/debug_lib_4dfd50.cpp) destroys the local map; most other static callbacks here are empty. Show/Start (`0x4dfd00`, `0x4dfe80`) parallel memory-window behavior with -performancestatus. Visibility (`0x4df280`) starts/kills200ms timer, restores/saves and hides; it does not destroy the HWND on ordinary close.

PerformanceDlgProc (`0x4df330`) forwards through window user data. HandlePerformanceMessage (`0x4df590`) registers Alt+Home, populates each combo with events allowed on that counter and initializes option checkboxes. Selection updates the chosen event, optionally pairs its related descriptor on the other counter and writes settings. Buttons toggle enabled/priority/debugger/window/autopairing; OK/Cancel hide; Help opens its authored intranet URL. EnableControls (`0x4df4e0`) requires both cached counter availability and enabled flag for the relevant controls.

On visible timer messages it persists changed position, locks the global report table and, if new keys changed it, rebuilds a private display map/list while preserving selection by name. SyncSelectedText (`0x4df380`) fetches current global report text and updates its edit only when different. It runs every timer pass, so replacement reports appear even when changed is false. Selected key/text are copied as a record, retaining a borrowed key pointer. No game simulation state is serialized into these preferences; the window displays reports submitted by profiled callers.

## Timer and reporting semantics

GetTimeSeconds (`0x4e1730`) calls QueryPerformanceFrequency/Counter each time and divides when both succeed, otherwise converts current UTC SYSTEMTIME to FILETIME seconds. The fallback is wall time, so it can jump; successful frequency is not separately checked for zero. This clock differs from GetTicks' display scaling and gameTick's simulation counter.

Timer constructors (`0x4e1d20`, `0x4e1d40`) invoke StartTimer (`0x4e1d60`); the one-argument form restarts a second time and discards the previous elapsed result. Start stores flags/borrowed name, appends a tab to a global indentation array without a bounds check, optionally raises thread priority and process HIGH_PRIORITY_CLASS, then restarts. Restart can read uninitialized prior time/stopped on a freshly constructed stack timer before overwriting them; the ignored first elapsed result is not a valid measurement. Destruction (`0x4e1de0`) decrements indentation, reports named timer and restores priorities if raised. Indentation/settings are shared, not per-thread nesting state.

While running, time is the start timestamp; while stopped it is accumulated elapsed. GetElapsedSeconds (`0x4e1e30`) returns stored elapsed or now minus start. Stop (`0x4e2150`) snapshots elapsed; Resume (`0x4e2160`) derives a new start; Reset (`0x4e2180`) sets zero/stopped; SetElapsed (`0x4e21c0`) writes elapsed or now minus it. AddElapsed (`0x4e21a0`) subtracts delta from stopped elapsed but adds it to a running start, reducing reported elapsed in both cases. The name must not be interpreted as an always-positive accumulation operation. [ComputeSampleRate](../../../src/debug/debug_lib_4e21f0.cpp) returns five divided by now minus the oldest of five history timestamps when positive, shifts history and stores now; history is not initialized by the shown StartTimer.

[RestartTimer and ReportElapsedTime](../../../src/debug/debug_lib_4e1e50.cpp) program/read two hardware counters when capability is cached, retain starting64-bit values and compute deltas at reporting. Report returns without even plain elapsed output unless profiling is enabled and counters available. It formats elapsed/name, low32-bit counts and a percentage when one event's related ID is the other's ID. Percentage denominator zero is not guarded, and large reports can overflow its500-byte temporary. Debugger output additionally requires global display setting and timer flag two; window output copies report into NameTable. Restart/Stop manipulate time, but Stop does not independently freeze the hardware delta used by a later report.

## Registry, window geometry and URL helper

CavedogRegistryKey (`0x4e2be0`) opens or creates HKCU/Software/Cavedog Entertainment/section/app, defaulting section when null. It overwrites its temporary handle at each level and its destructor (`0x4e2cb0`) is empty, so intermediate and final key handles are not closed here. ReadInt/ReadDword (`0x4e2d00`, `0x4e2d90`) require a4-byte REG_DWORD, clamp valid data to supplied signed/unsigned bounds and otherwise return caller default without clamping that default. Writes (`0x4e2d70`, `0x4e2e00`) ignore registry status. Boolean wrappers use low-byte defaults/writes.

ApplyDword/Int/Int2/Short/Word/Char/Bool/Byte (`0x4e2e20..0x4e3030`) choose read-and-clamp or write depending on readOnly, converting the final value to destination width. They do not make multi-value preferences atomic or guarantee a key exists. GlobalAllocFixed (`0x4e1a80`) is just GlobalAlloc with flags zero, not a tracked game allocation.

SaveWindowPosition (`0x4e3400`) skips iconic windows, saves current/normal rectangle and clamps edges at most minus500 to minus499 so they do not collide with the no-value sentinel. Only resizable windows save size/zoom. RestoreWindowPosition (`0x4e3080`) reads edges with minus500 sentinel, bounds saved dimensions to work area/minimum100 by50, retains fixed window size and clamps enough of the window onto the work area. Missing edges with unity zoom optionally show normal and return zero; other zoom factors resize without moving. A saved zoomed flag affects return for resizable windows but does not itself call ShowWindow maximized here. RestoreWindow (`0x4e33d0`) requests showing/sizing and discards the result.

GetFileNameFromPath (`0x4da590`) recognizes backslash only and returns a borrowed suffix. OpenUrl (`0x4da5b0`) first ShellExecutes the URL, then on result at most31 looks up extension association/open-command in HKCR and extracts executable before retry. Quoted command parsing removes the closing quote but leaves the leading quote in the passed buffer. Registry handles on failure paths are not all closed, fixed formatting is unbounded and null URL can still reach failure formatting. These are authored help links; no browser/network request was performed during tracing.

## Runtime string entry and exit-only support

The emitted basic_string::assign (`0x4e3c00`) resides physically in [basic_string.cpp](../../../src/runtime/basic_string.cpp) but belongs to this final module interval. Its body comes from the existing MSVC XSTRING header: reject source offset beyond length, clamp count to remaining, handle self-assignment with erases, share a full nonempty unfrozen buffer with equal allocator when reference count permits, otherwise grow/copy/terminate. It returns the destination reference. StringMaxSize (`0x4e3e10`) returns unsigned `0xfffffffd`. These are library support, not diagnostic report parsing.

Seven registration entries (`0x4e41e0..0x4e4240`) call atexit for empty callbacks; the six explicit tails (`0x4e4250..0x4e42a0`) and shared empty callback contain no shutdown work. Other empty allocator/name/memory/image-help local-static atexit bodies likewise do not release every pool, window, critical section or external handle. The performance map's generated teardown and explicit unload APIs have separate real lifetime behavior already described.

## Completion and limits

All267 owned annotations, the complete main file, twenty numbered companions, separately named allocator/dialog files and runtime string instantiation have been traced. Existing compiler VECTOR/XSTRING source, shared tree declarations, processor-event data and dialog-template declarations supply generated/data context. The writeup accounts for allocation/guard layout, ownership, loops, callbacks, persistence, clocks, no-ops and failure paths without changing source or claiming these original routines are universally safe. No builds, dependency installs, source listings, crash tests, live windows or driver calls were used.
