# Multiplayer connections, battle room, alliances and unit restrictions

Status: finished. `frontend/multi` owns 95 annotations in `0x440d70..0x44ce40`: 89 in [multi.cpp](../../../src/frontend/multi.cpp) and one each in [connection selection](../../../src/frontend/multi_443ff0.cpp), [provider clicks](../../../src/frontend/multi_4441a0.cpp), [provider construction](../../../src/frontend/multi_444580.cpp), [battle-room construction](../../../src/frontend/multi_449bb0.cpp), [battle-room update](../../../src/frontend/multi_44a680.cpp) and [restriction actions/cleanup](../../../src/frontend/multi_44c420.cpp). The last entry is an order-effect constructor sharing the interval. This module coordinates GUI and shared match setup, while HAPINET, packet queues and game protocol own transport and command application.

## Shared state and the route into a match

The frontend uses one global GUI layer stack, shared mission object, eleven physical player slots with ten ordinary playing indices, connection/provider buffers and one UnitSync object. Several local source views declare only ten players; routines that renumber slot ten are reaching the spare physical slot, not creating an eleventh participant. Player type zero is empty, one local human, two local CPU, three remote, and four blocked. Remote PlayerInfo.kind distinguishes human one from CPU two. Active, type, index sentinel ten, observer bit and living-unit tests are separate conditions, reused in different combinations.

[Frontend state dispatch](frontend-frontend.md) drives provider choice, address entry, session browsing, creation/join/watch, reporting and the battle room. Most actions request a future substate rather than opening a match immediately. Generic closing is controlled by [GUI activation semantics](gui-gui.md); handlers frequently leave the selected gadget active to allow closing, and clear it to keep a screen open. Cleanup callbacks use hot index minus one and are not equivalent to every named Cancel path.

Match rule fields are packed in the 185-byte PlayerInfo and advertised session description: resources are unsigned shorts in hundreds, width/height shorts, maxUnits a short, separate host/ready/observer/started flags, commander policy, mapping/LOS modes, watch/cheat permission, fixed starts and closed admission. These are lobby intentions until [game loading](game-game-load.md) and network startup apply them. Catalogue synchronization is described by [UnitSync](network-unit-sync.md), independently of live unit movement replication.

## Providers and compound address ownership

FillProviderList (`0x444580`) replaces an existing SELPROV.GUI, uploads/remaps the palette, opens a fresh layer and allocates provider descriptions (1280 bytes), ten GUIDs (160 bytes) and ten connection descriptors (80 bytes). It zeroes descriptor storage, refreshes multiplayer map discovery, uninitializes old multiplayer transport and asks HAPINET to enumerate providers. The wrapper has no caller-capacity parameter, so these allocations do not protect against an oversized provider enumeration.

It asks online.dll for service links and clones SERVICEX into dynamically named SERVICE buttons. CloneServiceSlot (`0x4444d0`) increments the layer count, copies a template, assigns translated text/name/y and activates it, without a gadget-capacity check. The link loop counts valid IDs until the returned count is reached; the DLL result's span/count ambiguity can make it scan past the reported range. DPLAY binds the borrowed provider descriptions; SELECT becomes the default choice.

HandleSelectProviderClick (`0x4441a0`) selects the DPLAY index, requests substate two and plays a button sound regardless of SelectConnection's return. SERVICE suffixes are atoi indices without an independent link bound. The callback sets the busy cursor, calls the online button adapter, and restores the cursor through its normal/catch paths. Result zero unloads the DLL and exits. Other results show returned text or a service-specific failure message. SETTINGS opens preferences; PREVMENU requests three. Cleanup frees GUIDs, all ten descriptor payloads, descriptors and descriptions only when the GUID pointer is nonnull; conns itself is not nulled. A partially allocated state can evade that guard.

SelectConnection (`0x443ff0`) accepts an explicit nonnegative index without an upper bound. A negative input consumes DAT_00512c80, choosing TCP/IP for one, IPX two, modem three, serial four, then resetting that preference to zero. It searches enumerated GUIDs for the requested provider. A resolved index copies GUID/descriptor and allocates an owned payload copy. Allocation failure sets selected size zero but still returns success one. Repeated selection does not first free a previous selected payload. Online password configuration copies at most ten characters plus termination into the password region.

GetServiceProviderIndex (`0x441bc0`) uses a different enumeration: modem zero, TCP/IP one, IPX two, serial three, other four. These indices must not be confused with the preference mapping above.

BuildCompoundAddress (`0x441c30`) constructs up to three DirectPlay address elements. Every case includes the selected service-provider GUID. Modem adds the first g_modemInfo string and NUMBER as phone data; TCP adds ADDRESS, substituting empty for null; serial adds the twenty-byte COM record after zeroing two fields and setting its final field three; IPX/unknown use only the provider element. It probes size and proceeds only on exact buffer-too-small `0x8877001e`, allocates, calls again and returns zero with output pointer/size on nonnegative completion. Failure frees the allocation through GlobalHandle/Unlock/Free and leaves outputs untouched. Fixed 200-byte temporary string buffers use unbounded copies. TryConnect (`0x442000`) initializes outputs to zero, saves the returned owned address on any nonnegative result and returns zero; no previous selected address is released here.

## TCP and serial screens

OpenTcpDialog (`0x4421f0`) opens TCP.GUI, initializes the lobby interface and fills ADDRESS from the command-line override or up to 128 registry bytes under TCPADDR. Command-line input invokes its handler immediately, then adjusts address-mode bit zero to host-mode truth. Otherwise it focuses ADDRESS and enables input.

HandleTcpDialogClick (`0x442050`) uses address-mode bits zero/one: OK or ADDRESS activation sets both; JOIN sets only one and clears zero. A command-line address also takes the connect path, clearing the override first for nonhost use. It attempts compound-address creation, plays a sound and writes 128 ADDRESS bytes to registry even when creation failed. The host/general path blanks the screen; JOIN does not. PREV requests state fifteen. These bits and a built address are not proof a remote session has been joined.

OpenSerialDialog (`0x442560`) binds four COM ports and six baud rates (115200, 57600, 38400, 19200, 14400, 9600), restores selected indices under SERPORT/SERBAUD and immediately invokes callbacks. SetSerialPortFromGadget (`0x4423a0`) accepts any nonnegative index and stores index plus one; SetSerialBaudFromGadget (`0x442380`) indexes its six-value table with any nonnegative index, without an upper check. The serial compound record includes the separately aliased baud field. HandleSerialDialogClick (`0x4423c0`) sets host/join bits, attempts address creation, stores successful outputs and persists the chosen indices, again without requiring success before sound/state effects. HOST blanks, JOIN does not; PREV requests fifteen.

## Modems and saved phone accounts

OpenModemDialog (`0x443100`) opens MODEM.GUI, initializes the lobby interface, creates a temporary modem DirectPlay interface and probes player-address size. On the expected size error it allocates/retrieves the address, allocates 200 zeroed bytes for modem names and enumerates address chunks. EnumModemAddressCallback (`0x443070`) reacts to the modem GUID, scans a double-NUL list, copies strings and increments modem count without checking dataSize or destination capacity.

Its NameSlot helper only advances beyond the first existing string, rather than walking to the end of every packed string. More than two names can overwrite the second name while count continues increasing. The later list can therefore claim more names than are represented. BuildCompoundAddress also reads the first name rather than consulting the MODEMS selection in this body.

No detected modems closes the layer, sets frontend error and requests state fifteen/substate zero, frees names/address and releases the temporary interface. This explicit path frees g_modemInfo without nulling it after a layer close that may itself invoke cleanup, so lifetime assumptions matter. Other failures can leave an incompletely populated dialog. The local temporary interface is released at the common tail even after failed creation; allocation results are not consistently checked before memset/use.

Successful setup allocates twenty 258-byte account records, each holding 129-byte name and number, plus 2560 bytes of packed display names. Registry MODEMNUMBERS is a 5160-byte binary block; missing data initializes each account to UNUSED and empty number. FillAccountList (`0x4426e0`) concatenates all names and preserves selection. RefreshAccountList (`0x4427a0`) actually copies edited NAME/NUMBER gadget text into the selected account before rebuilding, despite the source comment suggesting the opposite direction. ShowSelectedAccount (`0x4428f0`) copies the selected record to fields and focuses NAME. Bounds and string termination of restored account data are trusted.

SaveModemNumbers (`0x442970`) moves a positive selected index to record zero using a temporary and shifting earlier entries, then writes the whole registry block. HandleModemDialogClick (`0x442a30`) saves edits on NAME/NUMBER, advances focus, and for HOST/JOIN saves/reorders accounts and builds an address. Activating ACCOUNTS also falls through into the join path. HOST sets both address bits and blanks; JOIN sets bit one only and displays an abort message. PREV requests fifteen. Minus-one cleanup frees/nulls modem names, display names and account storage. The fixed display buffer can be smaller than twenty maximum-length names.

## Session discovery and advertised game columns

OpenSelectGameDialog (`0x443cb0`) opens SELGAME.GUI and allocates twenty 84-byte session descriptions, twenty 185-byte shared-data slots and fifteen 2560-byte packed column buffers. It binds each description's size/address to its shared-data slot and installs UpdateGameSelection on type-two list gadgets. It restores nickname/password, renders, discovers sessions and then focuses the game list. Discovery failure closes the layer and displays Invalid TCP/IP Address even when the underlying failure was not necessarily IP syntax. Nonzero reject reasons other than two are displayed/cleared. A command-line host with a nickname can proceed to creation automatically.

ConnectToGame (`0x441460`) shows Updating for TCP/IP/IPX and Connecting with Escape notice otherwise, presents twice, calls HAPINET_getgames, closes the message and rejects negative results. It clears all fifteen column buffers. For each returned session it formats packed name, occupancy/max players, trimmed/translated map suffix, status, memory, metal/energy times one hundred, ping limit, commander policy, map shading and command allowance. Version below the local value displays VER; otherwise Lock/Play/Open is based on advertised flags. Columns bind the session object's gameCount rather than independently reconciling that value with the return count. No local twenty-session/column-space cap is enforced during formatting.

UpdateGameSelection (`0x441220`) copies sixteen advertised bytes at record offset four into a padded local message and then copies all 185 bytes into the game buffer. Only that group is initialized, so the copy includes unrelated stack bytes. WATCH/JOIN disable-state bit zero incorporates empty list, advertised version below local and corresponding playing/watch/lock flags. The value read at group offset fourteen spans past the sixteen-byte group, although its version check uses only the low byte. Password gadget visibility comes from group.b bit zero. These preview gates are distinct from the final join checks.

HandleSelectGameClick (`0x4437c0`) UPDATE saves the password then re-enumerates. PREVMENU requests three. WATCH/JOINGAME or type-two activation copies the selected description into current game info and requires version exactly equal to local. Thus a newer version can appear eligible in preview but fail final joining. Lock `0x8000` or playing `0x10` rejects this common branch even for WATCH. It validates nonempty nickname, copies password, may mark battle-active from existing host started state, and sets observer bit six plus requested substate nineteen for WATCH, otherwise clears it and requests eighteen. STARTNEW clears observer, copies nickname, closes browsing and opens creation. Cleanup frees/nulls fifteen data pointers, shared storage and descriptions.

OpenNewMultiDialog (`0x441080`) restores nickname from online configuration or Windows username and sets name limits sixteen/password ten. Its online name global is a pointer-shaped byte alias into loaded configuration, used as an address. GetLocalPlayerPassword (`0x441430`) returns the local PlayerInfo address plus `0x80`, not a separately owned copy. HandleNewMultiClick (`0x440d70`) advances text focus, copies password, rejects empty game/nickname and copies both names into shared seventeen-byte fields. Stack copies are unbounded despite intended gadget limits. It starts score-report selection; when none is opened it requests substate seventeen. CANCEL returns to session browsing.

InitScoreReporting (`0x4436e0`) runs only for game type three. It saves cursor, loads the reporter DLL and, on result zero with a positive service count, opens REPORT.GUI and returns one. Result four is an allowed no-report path; other failures show an initialization message/background before restoring cursor and returning zero. External export/version contracts are in [statistics/reporting](game-statistics.md).

HandleReportClick (`0x443480`) OK reads at most sixteen active consecutive CHK controls, converts stage values into a powers-of-two mask, enables reporters and requests twenty-one when dirty bit four/current substate twenty is present, otherwise seventeen. It does not independently bound the opener's service count to sixteen. Unknown controls clear activation.

## Map and logo choice

ShowSelectedMapInfo (`0x444a20`) sets translated name, size/player text and description, frees any previous MAPPIC image, loads radar art and scales it using source dimensions shifted four. Missing controls/picture allocations and the 100-byte size text are not comprehensively guarded. OpenViewMapDialog (`0x444be0`) opens VIEWMAP and fills it. HandleViewMapClick (`0x444ba0`) OK plays a sound, while every other noncleanup activation clears selection; it does not explicitly free the picture in its cleanup branch.

UpdateMapSelection (`0x444c40`) loads the selected mission immediately into the shared object, disables MAPPIC on failure or refreshes it on success. Previewing therefore changes mission state before acceptance. HandleMapSelectClick (`0x444cb0`) accepts MAPNAMES/LOAD, loads without checking success, copies map/checksum into local PlayerInfo, broadcasts, reports event five and updates session info. It clears readiness for inactive or nonlocal-human/nonlocal-CPU slots. PREVMENU reloads g_oldMapName and broadcasts; minus-one frees MAPPIC text pointer, list data/layout and old-name buffer.

OpenMultiMapSelector (`0x444ea0`) allocates a 200-byte old-name buffer before checking HasMissionName. The false path shows no-maps and returns without freeing it. With a name it saves it, refreshes maps, rejects zero maps, opens SELMAP, allocates/sorts packed names, restores selection and invokes the same preview logic. The source preserves an original missing stack argument at RefreshMapList; the shown START caller invokes this opener precisely when HasMissionName is false, so that route returns before the defective call. Direct MAP activation can call the opener with a valid name; the initial guard alone is not a universal guarantee the later path is unreachable. This distinction follows the actual call sites rather than relying on the provisional “only caller” comment.

OpenLogoSelectDialog (`0x445110`) allocates a 32-byte layout, animation-pointer list and copies of logo sequences. A candidate j is excluded if any player whose type is neither zero nor four has color greater than or equal to j, without testing active. The comparison is not equality and can suppress every index up to a used high logo. Available indices are stored in the layout's first 24 bytes without a separate count bound. CacheLogosGadgetIndex (`0x444910`) sets hot index to LOGOS. HandleLogoSelectClick (`0x444930`) writes the selected available byte to local color, marks dirty and requests that color; cleanup frees sequences/list/layout. Cancel allows generic close.

## Dynamic player controls, sliders and rule stages

ExpandGadgetTextToType5 (`0x445300`) preserves a gadget prefix, truncates displayed text, shifts y two, converts a type-one control to type five and restores text with attribute `0x10`. BuildPlayerSlotGadgets (`0x4455b0`) resets count to the saved baseline and clones the ordered template set for ten rows, replacing each template name's last character by the player digit and offsetting y by twenty per row. Template position determines permissions: local name becomes text, other names gain `0x8000`; nonlocal logo/button state is read-only; local-human/CPU side controls differ; selected local/CPU controls are hidden; default controls become labels. It also assigns the local READY default/quick key and sets the slots-built latch. Missing templates and layer capacity are trusted.

SwapPlayerSlots (`0x4453a0`) swaps complete Player records, clears the source type/activity and renumbers indices zero through ten, using ten for invalid players. CompactActivePlayerSlots (`0x445450`) preserves live and blocked positions, moves later live players into holes and applies the same renumbering. Pointer-owned PlayerInfo moves with the record; external raw slot pointers are not stable identities across compaction. Several scans inspect the spare slot before their end check.

SetNamedSliderValue (`0x445e20`) resolves a slider then uses the shared value conversion. BindNamedSliderWithCallback (`0x445e50`) configures max, callback, converted initial value and game user pointer when found, but invokes the callback even for missing index minus one. Opening/rebinding sliders can mutate PlayerInfo and broadcast, not just display it.

UpdateMaxUnitsText (`0x445b70`) reads slider plus twenty when local host/no host, otherwise copies host maxUnits, writes local short and broadcasts when host. UpdateMetalText (`0x445c70`) and UpdateEnergyText (`0x445d60`) round slider values down to hundreds, store units of one hundred and, for local host, broadcast plus update session info. Metal repeats the same field store; this is not a second resource pool. Host/no-host and remote clients differ from unrestricted local game settings.

UpdateBattleRoomFlags (`0x445ed0`) uses host or local fallback: COMMANDER direct, MAPPING inverted, LOSTYPE two when LOS false, otherwise inversion of losType, WATCHING/ CHEATING/FIXEDLOC direct and GAMEOPEN inverted closed. UpdateSideGadget (`0x448bf0`) uses stage two for an active observer, otherwise side. These values determine presentation, not a generic truth-to-stage mapping.

HandleDisplayModesClick (`0x4461d0`) selects a mode by list index, writes configured width/height and local advertised shorts, broadcasts and saves. CANCEL/OK merely play their respective sounds and save here; CANCEL does not directly exit the process despite its source comment. Cleanup frees mode/name storage/layout. CyclePlayerDisplayMode (`0x446310`) enumerates/sorts modes and advances or reverses by clickMode two, wrapping around a matching current width/height. It updates config and broadcasts but does not recreate DirectDraw here. Allocated available-name storage is not freed by the cycle routine; only mode array/layout are freed. Failed/empty enumeration lacks a full fallback.

OpenRejectDialog (`0x446080`) saves a global target, opens YESORNO and formats its name. HandleRejectChoice (`0x446020`) YES calls RejectPlayer with target DPID/reason one; No permits closing. There is no local target bound/host validation in this handler itself. OpenControlDialog (`0x4466b0`) refuses an observer local player, opens CONTROL and populates other-player controls. UpdateWatchingGadgets (`0x446450`) reflects watch permission and inverted closed. It does not directly handle GAMEOPEN here.

ArePlayersAllied (`0x4467c0`) compares alliance numbers except sentinel five, which always means no team. CountPlayersInAlliance (`0x4467f0`) excludes five, requires active live types and index not ten, and in battle also requires unitCount nonzero or unitsCreated zero. FindNextAlly (`0x4469c0`) searches from an index for same non-five alliance/type nonzero, or the player itself regardless. It does not require every returned peer active.

SyncMutualAlliances (`0x446c70`) sets allied/alliedBy and shared-victory flag for found teammates, including self, then clears that flag when the counted alliance has fewer than two. It does not first clear every old relation. ClearAlliances (`0x446e90`) sends breaking relations to other active/selectable teammates and clears the initiating player's shared-victory bit. CyclePlayerAlliance (`0x446f50`) clears old team relations, advances modulo six, broadcasts, synchronizes and refreshes icons. RefreshTeamIcons (`0x446a50`) maps count zero to stage ten, singleton to alliance times two plus one, larger teams to alliance times two; battle uses compact icon positions, omitting eliminated/no-logo players.

OpenAlliesDialog (`0x4478b0`) opens ALLIES, sets orders-panel bit five, renames template controls sequentially and refreshes names/team/relations. VICTORY is grayed for team count above one or local observer. RefreshAlliesScreen (`0x447380`) compacts eligible nonobserver names/logos into rows and renames action controls LIVEPLYR/LIVEALLY with original slot IDs. It excludes local for control mode one, eliminated players during battle and color `0xff`; same-team alliance toggles are grayed. Local/CPU/remote CPU relations have different visibility. Name concatenation for pipe-state labels can overflow its 128-byte temporary.

RebuildAllyList (`0x446fb0`) updates only an active ALLIES screen, requiring active, nonobserver, live type/index, surviving-or-never-created and valid-logo targets, excluding self. ## Opening and refreshing the battle room

OpenBattleRoom (`0x449bb0`) resets room/player-ID latches, stores configured resolution and CD-present bit, opens LOUNGE2 and captures its template count. Host initializes maximum units from the configured limit. Online configuration can override lock, resources, unit cap, commander rule, LOS, cheat/watch permission, starts and mapping; some use one/two encoded choices, not Boolean truth. Otherwise host copies saved rules. Nonhost/locked settings controls are grayed. It allocates 2560-byte chatter, creates UnitSync, installs START sync/ready gates, binds resource sliders to maximum 10001 and unit count to maximum minus twenty, and refreshes map discovery. Online host can load a configured map. No named map triggers a fatal error. It publishes map/checksum, focuses MESSAGE, hides templates, builds rows and attaches battlestart animation.

RefreshBattleRoomRows (`0x448c70`) moves the chat read index by at most one when output exceeds visible line capacity, then copies ring text into packed chatter and sets list count. It reflects rules and map, reloads/refreshes changed map presentation, checks terrain exists and host map checksum for version at least two or 1.2, blinks missing-map color and clears readiness/broadcasts when the translated name differs. Legacy host versions accept existing terrain without checksum comparison. Nonhost MAP is grayed on invalid map. Shared mission state and translated display text participate in this detection, not just a separate immutable map ID.

It mirrors local readiness into every local human/CPU, rejects CPUs for commander policy two, removes observer bits when host disallows watching, synchronizes team relations/icons and rebuilds ten rows. Unused/blocked rows hide identity/status controls. Live rows show CD, logo, side/observer stage, two-way alliance, team, resolution, ping, memory tier and ready. Local readiness disables many edits. Only remote humans show numeric ping and optional :s from UnitSync; CPUs get n/a. Memory colors warn against map tier even in the n/a branch. Host updates advertised pingLimit downward to the minimum displayed remote-human ping, without raising it when conditions worsen.

UpdateBattleRoom (`0x44a680`) increments gameTick once per callback, handles packets, marks dirty on changes/bad map, and leaves on local rejection. Dirty work builds or compacts slots and republishes player count. Clients on LOUNGE copy host mission and sliders; VIEWMAP clients reload changed host maps. Host queries ready/synced, animates battlestart and toggles START/SYNCHING. Animation advances by one on deadline, adds four timer units, stops incrementing at frame eight and plays Panel at four. Ready starts frame one and pulsing START color, but this routine does not automatically invoke START when the animation finishes. Loss of ready does not explicitly reset the animation frame.

After drawing versions under logos and restoring GUI font it calls ProcessSync. On a strictly passed heartbeat deadline it refreshes CD-present and sends heartbeat, setting the next deadline to GetTicks plus sixty. GetTicks is display-scaled milliseconds, normally thirty ticks per second; sixty is normally two seconds, not a minute despite the provisional source comment. Battle-room gameTick is callback-driven here and should not be confused with exact elapsed wall time.

## Battle-room actions and launch validation

HandleBattleRoomClick (`0x447b10`) cleanup frees/nulls chatter, resets slots-built and synchronizes alliances. Its row actions include:

| Control | Work |
| --- | --- |
| LOGO | Local human/CPU requests next color and broadcasts. |
| PLAYER | Host can block an empty slot (type four, ID minus one, reduced session capacity), unblock it, remove an aged local CPU, prompt remote rejection, or add a local CPU if session is open, commander rule is not two and no local CPU exists. The branch sequence can unblock then create in the same activation. |
| SIDE | Observer becomes side zero; otherwise side increments/wraps. A wrapping local human may become observer when host permits it. Report event four and broadcast. |
| ALLY | Toggle local outgoing alliance; leaving a same numbered team breaks team relations and sets sentinel five. The sound test has retained operator precedence: incoming shifted one compared with three is always false for normal bytes, so outgoing alone effectively selects Ally sound. Announce and broadcast. |
| TEAMICONS | Cycle the target team and broadcast its team again after the helper's own broadcast. |
| RES | Local human cycles advertised/configured resolution. |
| READY | Local human checks map/CRC, copies gadget status into ready and mirrors local ready across local players; failure resets gadget only. Host readiness redirects default action to START. |

PREVMENU rejects every local human/CPU with reason two and requests three. MESSAGE recognizes exact case-insensitive +syncerr to show sync status; otherwise sends lobby chat and immediately flushes packet-manager queues when enabled. It empties and refocuses the edit. COMMANDER cycles zero/two; LOSTYPE cycles true elevation, circular and no LOS through two bits; WATCHING toggles permission and removes local observer state if disabled. CHEATING/FIXEDLOC toggle, MAPPING is inverse selected stage and GAMEOPEN stores inverse stage as closed. Relevant branches broadcast; advertised rule changes also update session description. RESTRICTIONS opens its nested UI. MAP opens selection for host and read-only view for clients.

START first counts disc-bearing local humans/remote human-kind peers: at least one is required, two for more than three humans and three for more than six. It rejects a team containing the full computer-plus-human total, then checks a named mission. Missing name calls the guarded map selector. If watchers are disallowed, remote observers are rejected with reason nine. It requests seventeen, sets started, updates advertised info, copies local LOS/commander/fixed-start/mapping into runtime config, saves and sets difficulty two. Ready and catalogue synchronization are principally UI enable/visibility gates computed elsewhere; this callback does not re-run both checks before its START branch. It also does not itself load terrain or spawn commanders.

## Restriction records, live edits and portrait loading

OpenUnitRestrictions (`0x44c7e0`) opens RESTRICT2 and allocates shared flags, per-item frame records (24 bytes each), packed text budgeted 32 bytes per definition, 98-byte restriction rows, portrait pointers and old counts. It skips definition zero and flag-two bit fifteen, formats internal name plus translated description/costs into each 82-byte row name, queries UnitSync and represents unlimited minus one as 101. It records old counts in definition iteration order, then case-sensitive qsorts rows by their name through CompareUnitRestrictEntries (`0x44c7a0`). Old counts remain unsorted deliberately for definition-order cancellation. Long descriptions can overflow both formatted record names and the smaller packed-text budget; allocation and query failures are largely unchecked.

DESCLIST and PICLIST share flag bytes and scroll metadata. Twelve SLIDER controls use themselves as callback data, maximum 101. A separate scroll slider has max 210; binding invokes UpdateUnitSliders before list configuration, followed by another explicit update. No independent guarantee enforces twelve valid rows at the current base, so short/end lists can access padding records or out-of-bounds storage. Host alone sees enabled Load/Save/Reset, but some handlers rely on this UI restriction rather than repeating authority checks.

HandleUnitCountSlider (`0x44be70`) parses the slider number from gadget byte offset eight, adds DESCLIST firstRow, reads the quantized value, maps values above one hundred to minus one/No Limit, updates row and calls SetUnitLimit. Shared flags mark peer-unavailable bit zero and zero-limit bit one. UpdateUnitSliders (`0x44bfd0`) handles twelve rows, grays when nonhost or peer-disabled, maps minus one back to slider maximum and invokes every slider callback, so merely refreshing a client view can call the setter with its current value. The UnitSync implementation determines actual permission/propagation; gray presentation is not an isolated security boundary.

ShowSelectedUnitCosts (`0x44c370`) looks up selected row's unit definition and shows integer energy/metal costs. LoadUnitPortrait (`0x44c0d0`) advances one row index per call, loads eligible unitpics/name.PCX, stores the owned surface and writes a frame descriptor. Missing art produces a width/height/null-data fallback but does not initialize every local descriptor field. It walks sorted rows and packs frames only for eligible entries; after exhaustion calls continue incrementing the load index. UnitRestrictDialogFrame (`0x44c220`) schedules one load after each strictly passed two-tick deadline and drains changed-catalogue events by FBI checksum, updating peer flags/limits. Any events trigger slider refresh, whose callbacks can write limits again.

HandleRestrictionsClick (`0x44c420`) opens list load/save, Reset changes restrictable max to one hundred or zero for definition flag bit sixteen, compares the row's previousMax field (zero-initialized here) before setters, and refreshes. Reset's one hundred is a finite limit, not unlimited. OK allows close. Cancel iterates original definitions and calls SetUnitLimit with old counts, where formerly unlimited was saved as 101 rather than minus one; it does not perfectly restore the unlimited sentinel. Row limits are edited live before OK.

Cleanup frees loaded surfaces, DESCLIST records/text, portrait array, rows, old counts, shared flags and PICLIST frames. Host also walks current rows and calls DisallowUnit for zero limits or AllowUnit otherwise before freeing rows. That policy happens on cleanup regardless of whether OK or Cancel initiated it. Only some globals are nulled; borrowed gadget pointers become invalid. The exact Allow/Disallow effects and catalogue notification ownership are in UnitSync, not a live-unit destruction pass.

## LST persistence, list dialogs and failure behavior

Despite names such as SaveGame and ListSaveGameFiles, these functions handle restriction .LST files, not full .SAV battle snapshots. LoadUnitRestrictListFile (`0x44b140`) reads a native little-endian integer count followed by pairs of definition FBI checksum and limit. It finds local definitions then matching restriction rows and stores max. SaveUnitRestrictListFile (`0x44b230`) declares count unitDefCount minus one and searches rows for each definition before writing checksum/limit. Skipped definitions can produce fewer pairs than the declared count. Neither checks fopen, fread/fwrite completion, count range or truncated input; they can crash or consume uninitialized values on invalid files.

ListSaveGameFiles (`0x44b4e0`) enumerates directory *.LST, allocates count times 256 for names/descriptions, zeroes, scans and initially binds filenames. Rebuilding does not free old arrays first. FreeSaveListBuffers (`0x44b100`) frees/nulls both. CopySelectedGameName (`0x44b330`) and ShowSelectedSaveGame (`0x44b600`) copy a nonempty selected display name to GAMENAME or blank it, then mark changed.

OpenSaveGameDialog (`0x44b990`) opens SAVELIST, creates the directory and strips filename extensions by scanning backward for a dot without a start bound. It binds names and editing, disables DELETE on an empty list, hides LoadGame and enables key commands. HandleSaveGameClick (`0x44b690`) DELETE removes the selected filename, rebuilds lists and reselection without checking the removal result; GAMES/LOAD/GAMENAME formats a .LST path from the typed name and saves if nonempty. CANCEL permits closing. Cleanup frees/nulls arrays, sets generic cleanup and clears game flag `0x38a51` bit zero.

OpenLoadListDialog (`0x44bc10`) opens LOADLIST, rejects empty lists with a message, strips extensions similarly, hides name/delete/save and sets the same flag bit. HandleLoadListClick (`0x44b3c0`) LOAD/GAMES builds the selected path, loads rows, temporarily switches GUI layer to the underlying restrictions layer for slider updates, restores it and frees/nulls list arrays. CANCEL and minus-one return without freeing those arrays or clearing the flag in this handler, so cancellation differs from successful load and save-screen cleanup. Neither list workflow provides transactional validation or a faithful complete game restore.

## End-of-multiplayer screen and interval tail

OpenEndMultiScreen (`0x44b020`) blanks, loads Mission02WinBW/palette, draws/frees its surface, flips, opens ENDMULTI and labels Victory/Failure from endgame bit four. Missing image/palette has no explicit fallback here. HandleEndMultiClick (`0x44afb0`) OK requests frontend state two and wider game mode one. Cleanup leaves the network game only when lobby UI flag four is set; the outcome bit is a different field.

OrderFx::OrderFx (`0x44ce20`) assigns its vtable and source argument only. Other order-effect/area behavior lies in [order targets](orders-order-targets.md); sharing this address interval does not make it a network-lobby allocation or a new packet type.

## Validation boundary

All 95 owned annotations and all seven implementation files have been traced, including out-of-address-order main-file bodies and split/gap companions. Provider/DLL/COM behavior, assets, translations and malformed files were not executed. The reference distinguishes callbacks from their downstream transport/gameplay effects, and identifies retained allocation, pointer, sentinel, map-selector and persistence limits.
